สัญญาการทำงานหนึ่งเดียวสำหรับผู้ช่วยเขียนโค้ด AI ทุกตัวที่คุณใช้งาน — Claude Code,
opencode, Codex, Cursor และ dsh harness ของ DeepSeek — ภายในชุดของ
repository roots ที่ได้รับการตั้งค่าไว้

หากปล่อยไว้ ผู้ช่วยแต่ละตัวจะมีนิสัยเฉพาะตัว: ตัวหนึ่งตอบเป็นภาษาตุรกี อีกตัวตอบ
เป็นภาษาอังกฤษ; ตัวหนึ่งใช้ grep ค้นหาทุกอย่าง อีกตัวคิวรีจาก code graph; ตัวหนึ่งบอกว่า
"เสร็จแล้ว" โดยไม่ได้รันการทดสอบ Tezgah ช่วยขจัดความคลาดเคลื่อนเหล่านี้ เปิดโฮสต์ใดก็ตาม
คุณจะได้รับภาษาเดียวกัน วินัยเดียวกัน และมาตรฐานของหลักฐานเดียวกัน

การออกแบบมีสองชั้น กฎต่างๆ จะอยู่รวมกันในแกนหลัก (shared core) เพียงที่เดียว; โฮสต์แต่ละตัว
จะมีอะแดปเตอร์ขนาดเล็กที่ทำหน้าที่แปลแกนหลักนั้นให้อยู่ในรูปแบบที่โฮสต์เข้าใจ
เปลี่ยนกฎเพียงที่เดียว โฮสต์ทั้งห้าตัวก็จะเห็นการเปลี่ยนแปลงนั้น — ไม่ต้องคัดลอกข้อความ
เดียวกันถึงห้าทาง

## สิ่งที่บังคับใช้

- **การรายงานผลลัพธ์ก่อนเป็นภาษาตุรกี (Outcome-first Turkish reporting)** ทุกการตอบกลับจะเป็นภาษาตุรกีและเริ่มต้นด้วยผลลัพธ์หรือการตัดสินใจ (BLUF) จากนั้นจึงชี้แจงประเด็นต่างๆ ตามลำดับผลกระทบ โค้ด, คอมมิต, เอกสาร และพรอมต์ของ subagent จะยังคงเป็นภาษาอังกฤษ; ชื่อ, คำสั่ง CLI และข้อความแสดงข้อผิดพลาดจะไม่ถูกแปลเด็ดขาด
- **โค้ดที่น้อยที่สุด (ponytail)** การเปลี่ยนแปลงที่ขี้เกียจที่สุดแต่ใช้งานได้จริง: YAGNI, จากนั้นใช้ helper ที่มีอยู่แล้ว, ตามด้วย stdlib, ฟีเจอร์เนทีฟของแพลตฟอร์ม, dependency ที่ติดตั้งไว้ และสุดท้ายคือโค้ดบรรทัดเดียว ไม่มีการทำ abstraction ที่ไม่ได้ร้องขอ การตรวจสอบความถูกต้อง (Validation), การจัดการข้อผิดพลาด และความปลอดภัย จะไม่ถูกลดทอนความซับซ้อนลงเด็ดขาด
- **การค้นหาผ่าน Code-graph ก่อน** "X อยู่ที่ไหน", "ใครเรียกใช้ Y", "อะไรจะพังถ้า Z เปลี่ยนแปลง" จะถูกส่งไปยังกราฟ `codebase-memory-mcp` (`search_graph`, `trace_path`, `search_code`) ไม่ใช่การใช้ grep การใช้ grep จะสงวนไว้สำหรับข้อความตรงตัว, คอนฟิก และไฟล์ที่ไม่ใช่โค้ด
- **การวิเคราะห์แอพผ่าน Accessibility ก่อน** การอ่านเว็บหรือแอพมือถือที่กำลังรันอยู่จะทำผ่าน accessibility / DOM / native view tree ไม่ใช่การจับภาพหน้าจอในแต่ละขั้นตอน `analyze-app` ครอบคลุมเบราว์เซอร์ (Playwright MCP), iOS Simulator หรือ Android emulator (Mobile MCP) และการวินิจฉัยเว็บที่เป็นทางเลือก (Chrome DevTools MCP); การจับภาพหน้าจอจะเป็นการกระทำที่ชัดเจนและทำเมื่อมีการร้องขอสำหรับสิ่งที่ tree ไม่สามารถให้คำตอบได้
- **ความเห็นที่สองจากภายนอก** ก่อนการตัดสินใจที่ไม่ธรรมดาหรือยากที่จะย้อนกลับ `~/.config/tezgah/bin/consult` จะสอบถามโมเดลอิสระผ่าน OpenRouter (หรือ DeepSeek API ด้วย `--provider deepseek`) แบบคู่ขนาน และเอเจนต์จะรายงานว่าโมเดลเหล่านั้นเห็นด้วยหรือไม่เห็นด้วยในจุดใด
- **การวิจัยผ่าน OpenResearch** เมื่อเราเตอร์ตัดสินว่างานนั้นคืองานวิจัย — การทบทวนวรรณกรรม, การสร้างและทดสอบสมมติฐาน, การรันการทดลอง, สิ่งประดิษฐ์จากการวิจัย — มันจะขับเคลื่อนงานผ่าน OpenResearch (`orx`) ของ alphaXiv และโหลดคู่มือ `orx` ก่อน แทนที่จะด้นสดโปรโตคอลเอง การค้นหาโค้ดธรรมดาจะยังคงอยู่บน code graph เมื่อไม่มี `orx` เราเตอร์จะแจ้งให้ทราบและถอยกลับไปใช้ subagent ของโฮสต์
- **ความซื่อสัตย์ภายใต้การตรวจสอบ** จะไม่มีการรายงานว่าเสร็จสิ้น, ทดสอบแล้ว หรือแก้ไขแล้ว เว้นแต่จะเห็นผลลัพธ์นั้นจริงๆ การทดสอบที่ล้มเหลวจะถูกรายงานว่าล้มเหลวพร้อมข้อผิดพลาดที่แน่นอน และการข้ามการตรวจสอบจะถูกระบุอย่างชัดเจน
- **ไม่มีการให้เครดิต AI ในทุกที่** สิ่งที่ถูกบันทึกหรือเผยแพร่ — ข้อความคอมมิต, การผสานโค้ด (merge), ข้อความแท็ก, ข้อความใน PR และ issue, คอมเมนต์ในโค้ด, ส่วนหัวของไฟล์, เอกสาร — จะต้องไม่ให้เครดิตผู้ช่วย, โมเดล, ผู้ให้บริการ หรือ "AI" การใช้เครื่องมือเป็นเรื่องปกติ; แต่การลงชื่อเครื่องมือในผลงานของคุณนั้นไม่ได้รับอนุญาต
- **การประสานงานแบบสองระดับ** เธรดหลักจะเป็นผู้ตัดสินใจและตรวจสอบ; โมเดลราคาถูก (`~/.config/tezgah/bin/codegen`, ค่าเริ่มต้นคือ OpenRouter หรือ `--provider deepseek`) จะร่างการแก้ไขที่มีขอบเขตและระบุรายละเอียดชัดเจนลงในไดเรกทอรีชั่วคราว (scratch directory) จะไม่มีอะไรเข้าสู่ repo ยกเว้นผ่านเราเตอร์ และหากการร่างล้มเหลว ระบบจะถอยกลับไปใช้โมเดลหลักโดยอัตโนมัติ
- **Subagent ประจำ repo** เมื่อเริ่มเซสชัน repo ที่ครอบคลุมอยู่จะได้รับชุดเอเจนต์ที่จำกัดความสามารถกลุ่มเล็กๆ (`tezgah-explorer`, `tezgah-reviewer`, `tezgah-researcher`, `tezgah-verifier`) พร้อมกับ `tezgah-orchestrator` ซึ่งจะถูกเรนเดอร์ลงในพื้นผิวเนทีฟของโฮสต์ที่ติดตั้งไว้ (Claude/Cursor `.claude/agents/`, opencode `.opencode/agents/` พร้อมการแทรกคอนฟิกแบบสด, Codex `.codex/agents/`) และถูกเพิกเฉยด้วยบล็อก `.gitignore` ที่จัดการไว้บล็อกเดียว บน Claude รายการอนุญาต `Agent(tezgah-*)` ของ orchestrator จะมีผลก็ต่อเมื่อมันรันเป็นเธรดหลัก (`claude --agent tezgah-orchestrator`); หากเป็น subagent รายการนี้จะถูกเพิกเฉย dsh ไม่มีพื้นผิวต่อบทบาท (per-role surface) ดังนั้นกฎเราเตอร์ของสัญญาจึงครอบคลุมส่วนนี้

## โฮสต์ที่รองรับ

| โฮสต์ | เชื่อมต่อโดย | แถบสถานะ |
|---|---|---|
| **Claude Code** | local plugin marketplace: hooks, คำสั่ง, เอเจนต์แบบอ่านอย่างเดียวสองตัว, รูปแบบผลลัพธ์ | native `statusLine` |
| **opencode** | ปลั๊กอิน + คำสั่ง + MCP + skill router ที่สร้างขึ้น (ปฏิเสธรายการ skill เนทีฟ), ทำดัชนี repo อัตโนมัติในข้อความแรก | ปลั๊กอิน TUI (ไม่มี command statusLine) |
| **Codex** | `hooks.json` + skills + MCP, รวมถึงเกต `PreToolUse` | hook `systemMessage` (รายการส่วนท้ายถูกปิด) |
| **Cursor** | `hooks.json` + skills + MCP | `statusLine` ใน `cli-config.json` |
| **dsh** | สะพานเชื่อม hook ของ Claude Code + บล็อกแพตช์ที่จัดการ (hooks, MCP, เส้นทาง LLM, แถบสถานะ Web นอกทรี) | ปลั๊กอิน Web UI: `tezgah-dsh-statusline` ในส่วนหัวของเซสชัน |

เกตของ Codex จะรัน Bash, `exec_command`, `apply_patch`, Edit/Write, เครื่องมือ MCP และการเรียก subagent ผ่านการตรวจสอบเดียวกันกับโฮสต์อื่นๆ บน Claude การแบนการให้เครดิตจะถูกบังคับใช้ทางกลไกเช่นกัน: การตั้งค่า `attribution` จะถูกทำให้ว่างเปล่า (`commit`, `pr`, `sessionUrl`) ดังนั้นเครดิตในคอมมิตและ PR จะถูกปิดตั้งแต่ต้นทาง

### แถบสถานะ

ทุกโฮสต์จะเรนเดอร์รายการตรวจสอบบรรทัดเดียวกันจาก `tezgah-status` ดังนั้นพวกมันจึงไม่สามารถคลาดเคลื่อนได้ สถานะคือจุดสำคัญ: เครื่องหมายจะเป็น **สีเขียว** เมื่อกฎถูกเปิดใช้งานและมีผลบังคับใช้ในเซสชันนี้, **สีเหลือง** เมื่อถูกเปิดใช้งานแต่เป็นแบบตามความต้องการ (ยังไม่ได้ใช้), และ **สีแดง** เมื่อ kill switch ปิดการทำงาน `idx` รายงานความพร้อมของกราฟแยกต่างหาก (`✓` ทำดัชนีแล้ว, `↻` เก่า, `✗` ยังไม่ได้ทำดัชนี, `–` ไม่เกี่ยวข้อง) และ `plans N (M blk)` คือแผนที่เปิดอยู่ `tezgah-status --legend` พิมพ์คำอธิบายสัญลักษณ์, `--json` ให้เซกเมนต์เดียวกันสำหรับ UI, และ `--no-color` (หรือ `NO_COLOR`) บังคับให้เป็นข้อความธรรมดา Claude Code และ Cursor จะให้สีแถบสถานะเนทีฟ; TUI ของ opencode จะให้สีคอมโพเนนต์ของตัวเองและรีเฟรชบน event bus ของโฮสต์; Web UI ของ dsh จะให้สีคอมโพเนนต์ส่วนหัวและรีเฟรชเฉพาะตอนที่แท็บนั้นแสดงอยู่; Codex แสดงสตริงธรรมดาใน `systemMessage`

dsh รันไฟล์ hook ของ Claude ตัวเดียวกันผ่านสะพานเชื่อม `dsh-hooks-claude-code` ดังนั้นสัญญาตอนเริ่มเซสชัน, เกตการให้เครดิต และการสะกิดให้ใช้กราฟก่อน grep ล้วนมีผลบังคับใช้ที่นั่น dsh เปิดเผยเครื่องมือ `subagent` เพียงตัวเดียว ดังนั้นการปฏิเสธ explorer ที่ใช้ grep อย่างเดียวจึงไม่มีผล — ไม่มี explorer subagent ให้มันปฏิเสธ แซนด์บ็อกซ์ `workspace-write` เริ่มต้นของ dsh จะจำกัดกระบวนการย่อยของ hook ให้อยู่ในเวิร์กสเปซและไดเรกทอรีชั่วคราวของแพลตฟอร์ม ดังนั้น tezgah จึงเขียนสถานะ hook ของมัน (เครื่องหมายการสะกิด, แสตมป์ดัชนี) ไปยัง fallback ที่เขียนได้ที่นั่นแทนที่จะล้มเหลวจากการถูกปฏิเสธการเขียน เวิร์กเกอร์ทำดัชนีกราฟไม่สามารถเขียนแคช `codebase-memory-mcp` จากภายในแซนด์บ็อกซ์นั้นได้ ดังนั้นตัวเรียกใช้งาน `dsh` จะอุ่นดัชนีในเชลล์ที่ไม่ได้ถูกจำกัดของผู้ใช้ก่อนที่จะบูต dsh — repo ใหม่จะถูกทำดัชนีเหมือนกับบนโฮสต์อื่นๆ ทุกประการ พร้อมประทับตรา HEAD เซสชันที่บูตโดยไม่มีตัวเรียกใช้งานจะยังคงได้รับรายงานที่ชัดเจนว่าเซิร์ฟเวอร์ MCP ที่ไม่มีแซนด์บ็อกซ์ให้บริการกราฟและต้องการ `index_repository` สำหรับ repo ที่ยังไม่ได้ทำดัชนี แทนที่จะเป็น `EPERM` ดิบๆ บล็อกแพตช์ที่จัดการยังประกาศเส้นทาง LLM ที่เข้ากันได้กับ OpenAI สองเส้นทางบนอะแดปเตอร์ pi-ai ที่การประกอบพื้นฐานเมานต์ไว้: `openrouter` (`OPENROUTER_API_KEY`) และ `deepseek` (`DEEPSEEK_API_KEY`) ซึ่งสามารถเลือกได้ควบคู่ไปกับค่าเริ่มต้น `deepseek-official` เนทีฟ คีย์จะถูกแก้ไขจากสภาพแวดล้อมการเปิดตัวหรือที่เก็บข้อมูลรับรองของ harness; ไม่มีคีย์ใดเข้าสู่ไฟล์คอนฟิก tezgah-setup ยังวางตัวเรียกใช้งาน `dsh` ไว้บน PATH (`~/.local/bin/dsh`) ซึ่งจะค้นหา CLI ที่ติดตั้งไว้ภายใต้ `$DSH_HOME` ดังนั้น `dsh --profile web` จึงทำงานได้จากทุกไดเรกทอรี

dsh ไม่มีแถบสถานะคำสั่ง ดังนั้น tezgah จึงจัดเตรียมปลั๊กอิน Web UI ให้: `tezgah-dsh-statusline` ครึ่งหนึ่งของโฮสต์จะให้บริการสตริง `tezgah-status` สำหรับเวิร์กสเปซของเซสชันผ่านเส้นทาง `/api/tezgah.status` ที่ผ่านการรับรองความถูกต้อง (ด้วย `?format=json` สำหรับมุมมองที่มีสี); ครึ่งหนึ่งของเบราว์เซอร์จะเรนเดอร์มันในส่วนหัวของเซสชัน โดยให้สีตามสถานะพร้อมคำอธิบายเมื่อชี้/คลิก และรีเฟรชเฉพาะตอนที่แท็บนั้นแสดงอยู่ `tezgah-setup` จะลิงก์ปลั๊กอินเข้ากับโปรไฟล์เว็บและเปิดใช้งานด้วยแถวที่จัดการใน `profiles/web/cordis.patch.yml` (เฉพาะเว็บเท่านั้น เนื่องจากครึ่งหนึ่งของโฮสต์จะแทรกบริการ `connection` ที่มีเฉพาะเว็บ); โปรไฟล์ที่ไม่เคยบูต `web` จะถูกข้ามพร้อมคำแนะนำแทนที่จะเขียนลงไปครึ่งๆ กลางๆ ในโหมด `headless` สะพานเชื่อม hooks จะแทรกสัญญา SessionStart เป็นเทิร์นต่อท้ายของมันเอง (การเรียก `agent/session-start` ของมันจะ `agent.inject()` แบบแยกส่วน หลังจากที่งานแบบครั้งเดียวเป็นข้อความแรกไปแล้ว) ดังนั้น `dsh --profile headless "<task>"` จะใช้เทิร์นเพิ่มขึ้นหนึ่งเทิร์น และสำหรับพรอมต์ที่ต้องการคำตอบตรงตัว จะพิมพ์ปฏิกิริยาของโมเดลต่อสัญญาแทนที่จะเป็นคำตอบของงาน; เซสชันเว็บแบบโต้ตอบจะไม่ได้รับผลกระทบ

`bin/tezgah-setup --install` ยังทริกเกอร์ `orx install-skills` สำหรับ Claude, Codex, opencode และ Cursor เมื่อ `orx` อยู่บน PATH ดังนั้นกฎการวิจัยจึงมีคู่มือให้โหลด ไฟล์ shim เป็นของ orx ดังนั้น tezgah จึงรันเฉพาะตัวติดตั้งนั้นและไม่เคยแสดงรายการเพื่อถอนการติดตั้ง dsh ไม่มี orx harness; กฎการวิจัยที่นั่นจะถอยกลับไปใช้ `orx skill` บนเชลล์

ปลั๊กอิน Claude ยังจัดเตรียมเอเจนต์แบบอ่านอย่างเดียวสองตัว `agents/tezgah-explorer.md` ทำการค้นหาโค้ดจากกราฟและส่งคืนหลักฐานแบบ `file:line`; `agents/tezgah-reviewer.md` เปลี่ยน diff ให้เป็นชุดผลกระทบด้วย `detect_changes` จากนั้นจึงค้นหาข้อบกพร่องที่แท้จริง ทั้งสองตัวถูกปิดใช้งานเครื่องมือเขียนและคำสั่ง; ผลลัพธ์ของพวกมันเป็นเพียงคำแนะนำ

### การวิเคราะห์แอพ

`analyze-app` ขับเคลื่อนแอปพลิเคชันที่กำลังรันอยู่จาก accessibility tree ของมัน ลูปเริ่มต้นคือเปิด, อ่าน tree, กระทำ, สังเกต console/network/logs, และอ่าน tree อีกครั้ง — การจับภาพหน้าจอเป็นการกระทำที่ชัดเจนสำหรับสิ่งที่ tree ไม่สามารถให้คำตอบได้ (canvas, เกม, แอนิเมชัน, การถดถอยทางภาพระดับพิกเซล) ทักษะนี้เป็นเส้นทางเดียวสำหรับทุกโฮสต์; เซิร์ฟเวอร์ที่อยู่ภายใต้มันคือสเปกที่แชร์ร่วมกันใน `hooks/tezgah_apps.py`:

| เซิร์ฟเวอร์ | เป้าหมาย | เชื่อมต่อโดย |
|---|---|---|
| `playwright` (`@playwright/mcp`) | หน้าเว็บ, เครื่องมือ `browser_*` | opencode, Codex, Cursor, Claude (ปลั๊กอิน `.mcp.json`) |
| `mobile-mcp` (`@mobilenext/mobile-mcp`) | iOS Simulator / Android emulator, เครื่องมือ `mobile_*` | เหมือนกัน |
| `chrome-devtools` (opt-in, `--devtools`) | ร่องรอยประสิทธิภาพเว็บ, เครือข่ายเชิงลึก, คอนโซลที่แมปซอร์ส | เหมือนกัน |

เบราว์เซอร์จะรันโปรไฟล์แบบ **แยกส่วน (isolated)** เป็นค่าเริ่มต้น ดังนั้นการรันจะไม่ไปแตะต้องสถานะ Chrome จริงของคุณ; การวิเคราะห์โฟลว์ที่ล็อกอินอยู่จะเป็นการแนบ (attach) โดยเจตนา (`--cdp-endpoint` หรือส่วนขยาย Playwright) ไม่ใช่ค่าเริ่มต้น ภาพหน้าจอ, ร่องรอย และการดัมป์ tree จะอยู่ใน `~/.cache/tezgah/apps` (แทนที่ด้วย `TEZGAH_ARTIFACTS`) และเอเจนต์จะได้รับเส้นทางกลับไป ไม่ใช่ไบต์รูปภาพแบบอินไลน์ เซิร์ฟเวอร์รันผ่าน `npx` ดังนั้นพวกมันจึงต้องการ node แต่ไม่ต้องติดตั้งเอง; `tezgah-setup --install --devtools` จะเพิ่มเซิร์ฟเวอร์การวินิจฉัยเว็บที่เป็นทางเลือก dsh เชื่อมต่อเซิร์ฟเวอร์สองตัวเดียวกันผ่านสะพานเชื่อม `dsh-mcp-client` ของมัน (`serverName` / `command` / `args` / `env` ซึ่งได้รับการยืนยันกับสคีมาคอนฟิกที่เผยแพร่) และ Claude ได้รับพวกมันจาก `.mcp.json` ของปลั๊กอิน (`claude plugin details tezgah` แสดงรายการเซิร์ฟเวอร์ MCP 2 ตัวและทั้งคู่เชื่อมต่อกัน) `mobile-mcp` เป็นครึ่งที่มีความเสียดทานสูงกว่า: macOS อาจแจ้งขอสิทธิ์ Accessibility / Screen-Recording และ view tree อาจตกหล่นภายใต้โหลด ดังนั้นทักษะนี้จะลองอ่าน tree ใหม่อีกครั้งก่อนที่จะถอยกลับไปใช้การจับภาพหน้าจอ

CI รันการจับมือ (handshake) แบบกำหนดได้สำหรับเซิร์ฟเวอร์ทั้งสองตัว (ไม่มีเบราว์เซอร์, ไม่มีอุปกรณ์): `TEZGAH_E2E_STRICT=1 python3 tests/e2e_analyze_wiring.py` การทดสอบควัน (smoke tests) ในพื้นที่แบบเลือกเข้าร่วมสองรายการจะไปไกลกว่านั้น: `TEZGAH_E2E_APPS=1 python3 tests/e2e_analyze_web.py` เริ่ม Playwright MCP, นำทางและอ่านสแนปชอตโดยไม่มีการจับภาพหน้าจอ; `TEZGAH_E2E_APPS=1 python3 tests/e2e_analyze_mobile.py` เริ่ม Mobile MCP, ตรวจสอบเครื่องมือ view-tree และแสดงรายการอุปกรณ์ พวกมันจะพิมพ์ `SKIP: ...` เมื่อไม่มี node, บิลด์เบราว์เซอร์ หรืออุปกรณ์

## การติดตั้ง

ต้องการ Python 3.8+ จำเป็นต้องใช้ node + npm สำหรับโฮสต์ dsh และด้วย `pnpm` สำหรับแถบสถานะเว็บของมัน การรวมระบบที่เป็นทางเลือกจะลดระดับลงอย่างนุ่มนวล: `codebase-memory-mcp` บน PATH ขับเคลื่อนกราฟ; คีย์โมเดลขับเคลื่อน `consult` และ `codegen` — ค่าเริ่มต้นคือ OpenRouter (`OPENROUTER_API_KEY` หรือ `~/.config/openrouter/key`) หรือ DeepSeek API ด้วย `--provider deepseek` (`DEEPSEEK_API_KEY` หรือ `~/.config/deepseek/key`); และ `orx` ของ OpenResearch บน PATH จะให้กฎการวิจัยมีบางอย่างให้ขับเคลื่อน เมื่อคีย์ของผู้ให้บริการที่เลือกหายไป tezgah จะแจ้งให้ทราบแทนที่จะแสร้งทำเป็นว่ามี

โคลน จากนั้นเปิดใช้งานทุกโฮสต์ที่ตรวจพบในรอบเดียว:

```bash
git clone https://github.com/r1z4x/tezgah.git ~/Projects/tezgah
cd ~/Projects/tezgah
bin/tezgah-setup --install
```

`--install` ยังติดตั้งเครื่องมือทางเลือกที่ขาดหายไปโดยรันตัวติดตั้งของผู้จำหน่ายแต่ละราย **ผ่านเครือข่าย**: `orx`
(`openresearch.sh/install.sh`), `cursor-agent` (`cursor.com/install`), `dsh`
(โปรไฟล์โฮมของมันผ่าน `npx`) และ `pnpm` เมื่อ dsh ต้องการ (ผ่าน `npm`) —
รวมถึง `curl ... | sh` ด้วย ไม่มีตัวไหนต้องการ sudo; การรันจะถูกบันทึกไว้ใน
`~/.config/tezgah/install.log` ดูตัวอย่างด้วย `--dry-run`, ข้ามด้วย
`--no-deps` (มีประโยชน์ใน CI) หรือติดตั้งเฉพาะเครื่องมือด้วย `--deps` เครื่องมือจะอยู่ใน `~/.local/bin` หรือ `~/.cargo/bin` ดังนั้นอาจต้องใช้เชลล์ใหม่ก่อนที่พวกมันจะอยู่บน PATH; การตรวจสอบของ tezgah เองจะค้นหาในไดเรกทอรีเหล่านั้นโดยไม่คำนึงถึงสิ่งใด ดังนั้นเชลล์แบบไม่โต้ตอบจะยังคงรายงานว่ามีพวกมันอยู่

หากมีการตั้งค่าก่อนหน้าอยู่แล้ว ให้นำเข้ามาก่อน — มันจะถูกย้ายออกไป ไม่ได้ถูกลบ:

```bash
bin/tezgah-setup --adopt
```

Claude Code ติดตั้งผ่านช่องทางปลั๊กอินของตัวเอง:

```bash
claude plugin marketplace add ~/Projects/tezgah
claude plugin install tezgah@rizacan-local
```

จำกัดการติดตั้งอย่างชัดเจนเมื่อจำเป็น:

```bash
bin/tezgah-setup --install --hosts claude,codex,opencode,cursor,dsh
bin/tezgah-setup --roots ~/work:~/oss --install
```

## การใช้งานประจำวัน

ไม่มีอะไรต้องรัน: กฎจะโหลดเมื่อโฮสต์เริ่มต้น มีคำสั่งสองสามคำสั่งที่ควรรู้:

| คำสั่ง | วัตถุประสงค์ |
|---|---|
| `bin/tezgah-setup` | รายงานสิ่งที่เปิดใช้งาน ในแต่ละโฮสต์ |
| `bin/tezgah-status [PATH]` | แสดงว่ากฎทำงานอยู่ใน repo นั้นหรือไม่ |
| `bin/tezgah-setup --status [PATH]` | พิมพ์รายการตรวจสอบที่เปิดใช้งาน/ใช้งานอยู่ |
| `bin/tezgah-setup --deps [--dry-run]` | ติดตั้งเครื่องมือทางเลือกที่ขาดหายไป (orx, cursor-agent, dsh) |
| `bin/tezgah-doctor [--clean] [--prune-sessions DAYS]` | รายงานการใช้ดิสก์ของ harness; `--clean` ลบบันทึกดัชนีเก่าและทำ vacuum ฐานข้อมูล opencode; `--prune-sessions` ลบเซสชันที่ไม่ได้ใช้งาน (การกระทำเดียวที่ลดขนาดฐานข้อมูลได้จริง) |
| `/plan-add` | เปลี่ยนชิ้นงานให้เป็นแผนที่ถูกติดตาม |
| `/plan-status` | สรุปแผนที่เปิดอยู่และเลือกแผนถัดไป |
| `/plan-sync` | ปิดแผนที่เสร็จสิ้นแล้ว |
| `bin/tezgah-setup --version` | พิมพ์เวอร์ชันของปลั๊กอิน |
| `bin/tezgah-setup --uninstall` | ลบเฉพาะ symlink ของ tezgah, รายการ hook ของโฮสต์ และบล็อกที่จัดการของ dsh |

<a id="configuration"></a>

## การตั้งค่า

Tezgah จะเปิดใช้งานเฉพาะภายใต้ root ที่ตั้งค่าไว้เท่านั้น; ที่อื่นมันจะเงียบ

- Root เริ่มต้น: `~/Projects`
- `~/.config/tezgah/config.json`: `{"roots": ["~/Projects", "~/work"]}`
- `TEZGAH_ROOTS` (รายการที่คั่นด้วยตัวคั่นเส้นทาง) จะแทนที่ไฟล์สำหรับการใช้งานครั้งเดียวและ CI

Kill switches อยู่ใน `~/.config/tezgah/` แต่ละตัวจะลบกฎของมันออกจากข้อความที่แทรกเข้าไปในเซสชัน ดังนั้นกฎจะหยุดทำงานจริงๆ:

| สวิตช์ | ปิดการทำงาน |
|---|---|
| `exec-mode.off` | ภาษาตุรกี, การรายงานผลลัพธ์ก่อน |
| `ponytail-auto.off` | กฎโค้ดที่น้อยที่สุด |
| `spec-off` | กฎสเปกก่อนสร้าง |
| `consult-off` | กฎความเห็นที่สองจากภายนอก |
| `research-off` | การกำหนดเส้นทางงานวิจัยไปยัง OpenResearch |
| `orchestrate-off` | การมอบหมายงานให้ subagent (เพิ่มบรรทัดห้ามมอบหมายงาน) |
| `reminder-off` | ข้อความเตือนความจำในแต่ละเทิร์น |
| `pretooluse-off` | เกต PreToolUse เอง (การให้เครดิต, explorer, การสะกิด grep) |

ในแต่ละ repo, `.no-ponytail`, `.no-cbm` และ `.no-lessons` จะปิดกฎโค้ดที่น้อยที่สุด, กฎ code-graph (และการทำดัชนีอัตโนมัติของมัน) และบัญชีบทเรียน ตามลำดับ

เมื่อผู้ใช้ตั้งค่าสถานะข้อผิดพลาด เอเจนต์จะต่อท้ายบทเรียนหนึ่งบรรทัดลงใน `.tezgah/lessons.md` ของ repo; บรรทัดล่าสุดจะถูกแทรกเมื่อเริ่มเซสชัน เพื่อไม่ให้ข้อผิดพลาดเดิมเกิดขึ้นซ้ำอย่างเงียบๆ

<a id="cost"></a>

## ค่าใช้จ่าย

วัดบนเครื่องนี้ (macOS, Python 3.10) ไม่ใช่การประมาณการ:

- **บริบท (Context)** การเริ่มเซสชันจะแทรกข้อความสัญญาประมาณ 4.8 KB (~1.2k โทเค็น) บน Codex จะมีข้อความเตือนความจำ 480 ไบต์ติดไปในแต่ละเทิร์น; Claude และโฮสต์อื่นๆ ไม่มี hook ในแต่ละเทิร์น ดังนั้นค่าใช้จ่ายต่อเทิร์นจึงเป็นศูนย์ ทักษะ `tezgah-contract` แบบเต็ม (~19.9k ตัวอักษร) จะถูกจ่ายก็ต่อเมื่องานโหลดมันเท่านั้น บน opencode สัญญาจะถูกส่งเป็นไฟล์คำสั่งขนาด ~5.5 KB มิฉะนั้น opencode จะแทรกข้อความชื่อ/คำอธิบาย/ตำแหน่งของทักษะประมาณ 53 KB ลงใน system prompt ของทุกเซสชัน; tezgah ปฏิเสธรายการนั้น (`permission.skill = deny`) และส่ง skill router ที่สร้างขึ้นขนาด ~16 KB แทน ดังนั้นทักษะจะถูกค้นพบโดยการอ่านเส้นทาง `SKILL.md` ของมันจากเราเตอร์
- **ความหน่วง (Latency)** Hooks เป็นกระบวนการ Python ที่แยกต่างหาก ดังนั้นการเริ่มต้นอินเทอร์พรีเตอร์ที่ ~19 ms จึงเป็นส่วนหลัก นอกเหนือจากนั้น การเริ่มเซสชันเพิ่ม ~25 ms, การเรียกเครื่องมือที่ผ่านเกต (Bash/Grep/Task) เพิ่ม ~9 ms และเซกเมนต์ Stop ของ Codex เพิ่ม ~15 ms ต่อเทิร์น
- **ดิสก์ (Disk)** การติดตั้งใช้เวลา ~58 ms และทุกไฟล์ที่ tezgah เขียนทับจะถูกเก็บไว้หนึ่งครั้งในชื่อ `<file>.tezgah-bak`

ผลตอบแทนจะแสดงให้เห็นในคำถามของผู้เรียกใช้ ใน repo จริงแห่งหนึ่ง `grep` เริ่มต้นเพิกเฉยต่อโฟลเดอร์ที่เกี่ยวข้องและไม่พบอะไรเลย; เมื่อปิดใช้งานการเพิกเฉย มันใช้เวลา 3.95 วินาที และยังคงผสมคำจำกัดความเข้ากับจุดที่เรียกใช้ (call sites) code graph ตอบคำถามเดียวกันใน 16 ms โดยแสดงรายการเฉพาะจุดที่เรียกใช้จริง 8 แห่งเท่านั้น

opencode ยังได้รับการติดตั้งเพื่อสุขอนามัยของบริบทในเซสชันที่ยาวนาน: `tezgah-setup --install` จะตั้งค่า `compaction.prune` เพื่อให้ผลลัพธ์ของเครื่องมือเก่าถูกล้างออกจากพรอมต์แทนที่จะถูกส่งใหม่ทุกขั้นตอน และรายการ `watcher.ignore` จะกัน file watcher ออกจาก `.git`, `node_modules` และไดเรกทอรีบิลด์ ทั้งสองอย่างจะถูกผสานรวมกัน — ค่าที่ผู้ใช้ระบุอย่างชัดเจนจะชนะ สิ่งนี้สำคัญเนื่องจาก opencode จะทำ auto-compact ใกล้กับขีดจำกัดบริบทของโมเดลเท่านั้น (สำหรับโมเดล 1M-token คือประมาณ 980k) ดังนั้นหากไม่มีการตัดแต่ง (pruning) ชุดการทำงานจะขยายเป็นหลายแสนโทเค็น `bin/tezgah-doctor` จะรายงานพื้นที่ดิสก์ที่ใช้ไป; `--prune-sessions DAYS` จะลบเซสชันที่ไม่ได้ใช้งานผ่าน opencode CLI ซึ่งเป็นการกระทำเดียวที่ลดขนาดฐานข้อมูลได้จริง — VACUUM เพียงอย่างเดียวไม่สามารถทำได้ เนื่องจากเพจของมันยังคงใช้งานอยู่ทั้งหมด

<a id="development"></a>

## การพัฒนา

```bash
python3 -m unittest discover -s tests -v   # stdlib test suite
pip install -r requirements-dev.txt        # pinned ruff, the only dev dep
ruff check .                               # lint (config in pyproject.toml)
```

CI รันทั้งบน Python 3.10 และ 3.12 หากต้องการรีเฟรชสำเนา Claude ที่ติดตั้งไว้จากการเช็คเอาต์นี้ ให้ใช้ `bin/tezgah-setup --sync` และตรวจสอบความถูกต้องของ manifest ด้วย `claude plugin validate .claude-plugin/plugin.json` เมื่อทำการเพิ่มเวอร์ชัน ให้อัปเดต `.claude-plugin/plugin.json` และ `.claude-plugin/marketplace.json` ไปพร้อมกัน — ทั้งสองไฟล์ต้องตรงกัน

`codebase-memory-mcp` ถูกติดตั้งโดยผู้ใช้ hooks และไฟล์ของ Orca ไม่ได้เป็นส่วนหนึ่งของโปรเจกต์นี้และจะไม่ถูกแตะต้อง Claude ได้รับแกนหลักที่เปิดใช้งานตลอดเวลาจาก hook SessionStart; `output-styles/tezgah.md` เป็นไฟล์ที่ทำซ้ำสำหรับบิลด์ที่โหลดรูปแบบผลลัพธ์ของปลั๊กอิน ดังนั้น hook จึงเป็นเส้นทางที่เชื่อถือได้

<a id="contributing"></a>

## การมีส่วนร่วม

การเปลี่ยนแปลงเล็กๆ ที่มีจุดประสงค์เดียวจะได้รับการยอมรับง่ายที่สุด กฎควรอยู่ในแกนหลักที่แชร์ร่วมกัน (`hooks/`) เว้นแต่จะเป็นเฉพาะเจาะจงสำหรับโฮสต์จริงๆ; ความแตกต่างของโฮสต์ควรอยู่ในอะแดปเตอร์ภายใต้ `hosts/<name>/` รักษา diff ให้สั้นที่สุดเท่าที่จะเป็นไปได้ในขณะที่ยังคงถูกต้อง — กฎโค้ดที่น้อยที่สุดของโปรเจกต์นี้ก็มีผลบังคับใช้กับตัวโปรเจกต์เองด้วย

ก่อนที่จะเปิด pull request ให้รันการตรวจสอบสามอย่างแบบเดียวกับที่ CI รัน:

```bash
python3 -m compileall -q hooks hosts bin statusline.py   # byte-compile every script
python3 -m unittest discover -s tests                     # stdlib test suite
ruff check .                                              # lint; config in pyproject.toml
```

`ruff` มาจาก `requirements-dev.txt` (`pip install -r requirements-dev.txt`) ซึ่งเป็น dependency สำหรับการพัฒนาเพียงตัวเดียว

## ความปลอดภัย

รายงานช่องโหว่แบบส่วนตัวผ่านคำแนะนำด้านความปลอดภัยของ GitHub (แท็บ **Security** → **Report a vulnerability**) แทนที่จะเปิดเป็น issue สาธารณะ

tezgah รัน shell hooks, เขียนคอนฟิกของโฮสต์ และแทรกข้อความลงในทุกเซสชัน ดังนั้นสิ่งใดก็ตามที่ทำให้ hook รันโค้ดที่ผู้โจมตีควบคุม, ทำคีย์รั่วไหลลงในไฟล์คอนฟิก, ขยายแซนด์บ็อกซ์ หรือปล่อยให้เนื้อหาใน repository ยกระดับเป็นข้อความคำสั่ง ถือว่าอยู่ในขอบเขต โปรดระบุโฮสต์, เวอร์ชันของ tezgah (`bin/tezgah-setup --version`) และวิธีการจำลองปัญหาแบบย่อ
