# 2608.28795 — The reach of a verification tool decides its value

Achint Mehta. alphaXiv: https://www.alphaxiv.org/abs/2608.28795 — 2026-08-28.
Read in full (alphaXiv full text; abstract + introduction).

## What it is
A dose-response study of the *verification surface* — the tools an agent uses to check
its own work. A minimal harness whose tool list is the single controlled variable;
1,116 web applications built by 6 models across 8 tool configurations; every artifact
graded blind by a human against a frozen rubric, plus automatic API probes.

## The findings that bear on tezgah
- **"Verification's cheapest benefit arrives first."** With no tools, about one build in
  seven fails to launch; a **single boot probe removes nearly all of those failures at
  ~35% of a full shell's token cost**, while the full shell multiplies the no-tools token
  cost by 2.35. The first rung buys the most.
- **"A verification tool improves the output artifact only where its reach covers the way
  the application actually fails."** Screenshots help where failures are visible (element
  placement, interaction) — modestly, and the gain does not survive correction for
  multiple comparisons; they add nothing where failure can only be measured.
- Two sibling results the paper cites frame it: SWE-agent's interface alone can roughly
  triple resolution; Agentless is competitive with full agents at a tenth of the cost.

## Quality and limits
Formal-ish record (submitted to IEEE; single author; no external funding). One grading
pass per artifact by a human; visual gains are explicitly reported as suggestive, not
established; one task family (web applications).

## Why it is in this line
It supplies the yardstick for E2's zero-fire rules: a rule's reach either covers how the
work in hand actually fails, or it is a cost with no artifact behind it. The paper's own
phrasing is the test to apply to `explorer` and `order`.
