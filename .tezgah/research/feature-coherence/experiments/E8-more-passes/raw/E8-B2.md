Objective (one measurable outcome, and its chain):

- **Goal** — an operator can grant, change and revoke a person's access to the organization
  without leaving the panel and without the database.
- **Signal** — an access change that the affected person can act on (an added member who can
  sign in; a removed member whose sessions are gone).
- **Metric** — *invite completion ratio*: invitees holding at least one successful panel/mobile
  session within 7 days ÷ invitees created in the same window, per organization. Today this is
  **unmeasurable** (`analytics: false`, no-op sink — `code`), which is why the row exists but
  carries no number. Counts are refused: `1 kullanıcıdan 1 kayıt gösteriliyor`
  (`ui-observed`, `page.tsx:163-165`) is a windowless, denominator-less count and is not used as
  evidence of anything.

## 2. Opportunities (a need, never a feature)

No `user-verbatim` evidence was reachable this session, so these are not claimed as user needs;
each carries the class of its actual support.

- **O1** — "I must give a new colleague working access without touching the database, and I must
  be able to take it back." Support: `code` (F1, F2) + `ui-observed` (the button exists; the
  identity that sees it cannot complete it). *Hypothesis, to be confirmed with a `user-verbatim`
  source.*
- **O2** — "I must see who currently has access, and to what, without scrolling sideways."
  Support: `ui-observed` (F3 — 56 px of the last column is outside the visible region at 1440).
- **O3** — "When I filter, I must be able to express the state I see in the table." Support:
  `ui-observed` + `code` (F4).

Candidate solutions for O1, against a pre-stated criterion — *criterion: the invited person can
authenticate with no help from the operator, and the operator's action is auditable*:

| # | Solution | Against the criterion |
|---|---|---|
| S1 | Add an invitation record (token hash, expiry, consumedAt) and send it by email via the provider the repo already uses for password reset | meets both halves; needs a schema migration and an expiry policy |
| S2 | Mail the generated temporary password on invite, force a change at first sign-in | meets authentication, fails auditability of acceptance (no accepted-at fact) and stores a credential in transit |
| S3 | Email a deep link into the existing password-reset flow instead of a password | meets authentication and auditability with no new credential, but needs the invitee to be pre-identified by email and gives no expiry control |

S1 is recommended (see the capability-change proposal); S3 is the cheapest and is what Clerk and
Supabase both do in effect (see §7).

### Findings at their level

Levels are the depth ladder (screen / component / state / property). Severity is the
frequency × impact × persistence read on the 0–4 scale.

1. **F3 · component + property · severity 3 · `failure` (measured)** — the data view clips its own
   per-row control. Measured `tableWrap` `scrollWidth/clientWidth`: **1140/1084** at 1440, **1140/686**
   at 768, **1140/312** at 390, and the last column `Yetki güncelle` occupies **x 1064 → 1443**
   while the wrapping card's right edge is **1387** — 56 px of the table is outside the visible
   box at the default desktop width, 828 px at 390. `overflow-x: auto` gives the region a
   keyboard-scrollable path (`role=region`, `tabindex=0` — a pass), but there is no fade,
   scrollbar hint or width strategy, and `td/th` are `white-space: nowrap` with no truncation
   (`globals.css:568-574`). axe cannot even decide the cell's contrast: the incomplete node
   `td:nth-child(7) > p` reports *"partially obscured by another element"*. Read from the
   rendered image too (`E8-B2-users-1440.png`, `-390.png`): the text is cut mid-word at the card
   edge. Standard: feature-audit's data-view rule "A scroll region says it scrolls".
2. **F4 · screen + state · severity 3 · `failure`** — the filter vocabulary is narrower than the
   vocabulary the table renders, and an unknown value fails open. The table prints
   `userStatusLabels` keys `ACTIVE, INVITED, SUSPENDED, DEACTIVATED, DELETED`
   (`user-labels.ts:16-22`) while the stored enum is `INVITED, ACTIVE, SUSPENDED, ARCHIVED`
   (`apps/api/prisma/schema.prisma:39-44`) and the list endpoint already excludes `ARCHIVED`
   (`users.service.ts:28-31`); the filter offers only "Tümü / Aktif / Pasif" against
   `membership.active`. Measured: `?state=bogus` renders all rows with the select reading
   "Tümü" and `value=""` — the URL says one thing, the control says another, the data ignores
   both.
3. **F8 · screen · severity 2 · `judgement` (1 rater)** — a filtered result is announced to
   nobody. The loaded page carries **zero** `[role=status]`/`[aria-live]` nodes (measured), and
   the result line is plain `.muted` (`page.tsx:163-165`); under a client-side transition the URL
   and the count change with no announcement. SC 4.1.3, which axe has no rule for. Judgement
   because a full-navigation filter does move the reading position; the client-side transition I
   observed does not.
4. **F9a · component · severity 2 · `failure` (measured)** — the data view has no row hover or
   selection state: `grep 'tr:hover|tbody'` over `globals.css` returns zero matches and the
   measured row background is unchanged under the pointer. Every other interactive surface in the
   area has one (button, nav link, secondary button) — the deviation is from the product's own
   convention.
5. **F9b · property · severity 2 · `failure` (measured)** — `th` is `font-size: 13px`
   (`globals.css:575-578`), an absolute length: at a 200 % root font size the body goes 16→32 px,
   `h1` 32→64 px and `td` 16→32 px, while `th` stays **13 px** (measured). SC 1.4.4 is met for
   content and not for the header labels.
6. **F7 · state · severity 2 · `judgement`** — opening the modal puts focus on the close button
   (`aria-label="Pencereyi kapat"`, 36×36), not on the first content control; the APG dialog
   pattern sends initial focus to the first focusable element in the dialog content. Reproduced
   with a real `page.mouse.click` on the trigger (so the trigger was focused first), then read
   `document.activeElement`.
7. **F9c · screen · severity 1 · `judgement`** — the screen has three headings and no breadcrumb
   semantics issue (`Platform / Yöneticiler` is a plain header), the h1 is the page title while
   the card's h2 is "Kullanıcılar"; the primary action is a 1126 px full-width bar at desktop,
   which by the blur test reads as a banner before it reads as a button. Not a defect by itself;
   recorded because the image test is what shows it.

## 8. Findings, most severe first, each with its class and its citation

Class is exactly one per finding. Where two classes are named, the first is the finding's own
class and the second is corroboration.

1. **F1 — the invite action is dead for the only identity that can reach it.** `ui-observed` +
   `code`. The form's role select offers exactly one option, preselected: `SUPER_ADMIN/Platform
   sahibi` (measured: `[...options]`, `new FormData(form)` → `roleKey=SUPER_ADMIN`); the panel
