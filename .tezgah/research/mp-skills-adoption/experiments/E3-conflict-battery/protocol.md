# E3 protocol — which conflicts are mechanical, and which are only policy?

**Change under test:** none to the repository; three executable probes. The
question is whether adopting the pack's text would be *stopped by something that
runs*, or only by a rule a human has to remember.

## Probes and predictions

**(a) The floating tag.** `tests/test_skills.py:92` rejects
`[\w@./-]+@latest\b` anywhere in `skills/*/SKILL.md` plus `NOTICE`. The pack's
install wording (`npx skills@latest add mattpocock/skills`) lives in its READMEs,
not in a `SKILL.md`.

*Predicts:* **0 hits** in the suite's own corpus (`skills/**/SKILL.md`) and **≥1**
in the pack's wider markdown corpus. The collision is therefore a *packaging*
risk — text that travels with an adopted skill — not a *body* risk.

*Falsified by:* ≥1 hit in the `SKILL.md` corpus (grafting a body alone breaks the
suite), or 0 hits in the wider corpus (the wording is not there at all).

**(b) The attribution gate.** The pack's `triage` skill mandates that every
comment it posts opens with a generated-by-AI line (`skills/engineering/triage/
SKILL.md:15-17`), and tezgah's contract bans AI attribution on any host. The
attribution rule's anchor set is `co-authored-by|generated with|made with|built
by|assisted by|authored by|noreply@anthropic|🤖` (`hooks/tezgah_gate.py:151`),
and `gh issue comment` *is* a write command it reads.

*Predicts:* the mandated line is **allowed** — "generated by AI" is not "generated
with" — so the conflict is **policy-level**: nothing mechanical stops a session
that follows the adopted skill from publishing an AI-attribution line.

*Falsified by:* `attribution()` returning true for the mandated line.

**(c) The suite, against a grafted candidate.** Two variants in a scratch clone
(`git clone --local`): one candidate body carrying the float string, one without.

*Predicts:* the tagged variant fails **≥1** test with the repository otherwise at
HEAD, and the plain variant fails **0**. That separates "the pack's text trips a
guard" from "grafting a skill trips a guard".

*Falsified by:* the plain variant failing any test (the graft itself is the
cause), or the tagged variant failing none (the predicate does not reach a
grafted body).

## Instrument

`instrument.py conflicts --upstream /tmp/mp-skills/skills --repo . --clone
--graft tag` (and `--graft plain`), plus `attribution()` read in-process from
`hooks/tezgah_gate.py`. The suite probe's scope is `fixture`: a clone at HEAD.
