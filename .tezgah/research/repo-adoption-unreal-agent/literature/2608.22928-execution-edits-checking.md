## What it gives

The hazard, stated exactly: Checkpoint, Fork, Restore and Merge are "execution edits",
and "an execution edit cannot undo an earlier authorization or a tool request already
sent. An unsafe edit can therefore authorize the same tool action twice, discard a result
the task still requires, or conflict with a call that began before the edit." Because the
agent is untrusted, the runtime uses its execution record to decide which past actions an
edit must account for and which required results it must preserve, and the check is exact
rather than heuristic.

## What it means for tezgah

tezgah has no runtime to check, so the portable part is the **checklist**, not the
checker. A derivation-shaped state is safe only when three questions are answered: what
in-flight work exists, what authorizations have already been issued, and what results the
task still requires. Applied to the repository under survey, this converts
`// FIXME: Forks leave inherited calls without results and retain pending-input
accounting.` (`harness/coordinator/loop.go:552`) from an apology in a comment into a
named, published open finding.

For tezgah the same three questions apply to every place it derives one artifact from
another — a research line opened from another, a plan split into two, a session carried
across hosts — even though the state is files rather than a runtime value. That is the
`adapt` verdict in this line's report: one checklist in an existing skill, no new file.
