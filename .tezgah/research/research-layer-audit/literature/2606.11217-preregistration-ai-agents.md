## Claim

Agent experiments multiply *researcher degrees of freedom* beyond the behavioural
sciences: model family **and version**, prompt wording, system instructions,
sampling parameters, context length, tool access, retry rules, response parsing,
refusal handling, inference budget. Individually defensible choices made after
seeing results inflate the apparent evidential strength of a finding without
anyone committing fraud. The proposed preregistration template therefore adds, to
the usual hypotheses/samples/measures, fields for exact model identifiers, API
versions, prompt text, decoding settings, inference budgets, context construction,
response handling and **pilot-testing history** (how many prompt iterations, which
models were tried, whether preliminary results shaped the hypotheses).
Confirmatory and exploratory analyses must be labelled separately.

The paper's empirical illustration: a 2,430-configuration anchoring simulation
spanned reverse anchoring, no effect, and effects stronger than the cited human
range - so a single reported configuration cannot establish a stable behavioural
property. It distinguishes **reproducibility** (same pipeline, same output) from
**credibility** (was the reported pipeline selected by undisclosed searching?).

## Why it matters here

`skills/research/SKILL.md` already has the preregistration *instinct* -
`protocol.md` committed before the run, a locked metric and baseline,
CONFIRMATORY/EXPLORATORY labels. What it has no field for is the environment, and
in an agent-research repo the environment is the model version, the prompt, the
harness configuration and the retry rules. E1's P1/P2/P3 show the checker reads
none of it.
