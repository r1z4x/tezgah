# ActPlane: Programmable OS-Level Policy Enforcement for Agent Harnesses

- id: alphaXiv 2606.25189 (arXiv preprint), 2026-06-23
- authors: Yusheng Zheng, Tianyuan Wu, Quanzhi Fu, Tong Yu, Wenan Mao, Tao Ma, Dan Williams, Wei Wang, Andi Quinn
- affiliations: UC Santa Cruz, Virginia Tech, HKUST, eunomia-bpf, Alibaba Group
- url: https://www.alphaxiv.org/abs/2606.25189
- read: alphaXiv report, 2026-09-19 (report, not the PDF)

## Claim

Policies written in a harness instruction file (`CLAUDE.md` / `AGENTS.md`) are
enforced by one of two mechanisms today, and both leak:

- **tool-call guardrails** (AgentSpec, Progent, FIDES, CaMeL) intercept the tool
  layer and are blind to *indirect system actions* - a command run inside a
  script or a compiled binary never passes the tool layer.
- **OS sandboxes** (seccomp, AppArmor, Landlock, Tetragon) see everything but
  are static, act on resource access rather than on semantic action, and return
  an opaque `EPERM` the agent cannot act on.

Their answer is programmable enforcement in-kernel (eBPF) with semantic feedback.

## Evidence they measured

Empirical study of 64 popular GitHub repositories carrying instruction files:

- 64% of the statements are behavioral policies.
- 83% of those involve system actions - i.e. an OS-level view is needed to see
  them at all.
- 16% are *cross-event*: they constrain ordering or data flow across more than
  one operation ("A must precede B"; "data from X must not reach Y"). These
  concentrate in development workflows.

## Why it matters here

This is the strongest external confirmation of two things tezgah already
documents about itself as open holes:

1. `docs/gate.md` records that a write through the shell outside the root, and a
   `python3 -c "open(...).write(...)"`, are outside the pattern table
   (`hooks/tezgah_gate.py:736-738`). ActPlane names that whole class as the
   structural failure of tool-call guardrails, which is what tezgah's Python
   half is.
2. tezgah has **no cross-event rule at all**. E7b/E7c added "a reading phase
   refuses a shell write", which is a per-call shape, not an ordering policy.
   ActPlane's 16% and FAVA's 90% (see 2607.27267) both say ordering is where
   real instruction files put their weight.
