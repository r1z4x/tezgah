# Runtime Compliance Verification for AI Agents

- id: alphaXiv 2606.19242 (arXiv preprint), 2026-06-17
- authors: Nafiseh Kahani, Masoud Barati, Diana Addae (Carleton University)
- url: https://www.alphaxiv.org/abs/2606.19242
- read: alphaXiv report, 2026-09-19

## Claim

Agent compliance is a **runtime verification problem over event traces**, not a
static property. Their framework (C-Trace) instruments the agent loop into a
typed event sequence

`τ = e1 e2 … en`, each `ei ∈ {UserMsg, AsstMsg, ToolCall, ToolRet, Consent,
Erasure}`,

annotates each event with data categories and purposes, and evaluates
first-order policy predicates **incrementally over trace prefixes**. The
predicates are chosen to be *monotone*: once violated, a later event cannot
undo it. Violations are detected before the action executes or the content is
disclosed.

Evaluation includes a cross-formalism check - the same policy implemented as a
Python monitor, as Rego/OPA, and as an MFOTL specification, with all three
required to agree on every event trace.

## Why it matters here

Two transferable pieces:

1. **The event model is tezgah's ledger, renamed.** `turn` ≈ `UserMsg`,
   `claim` ≈ `AsstMsg`, `run`/`verify` ≈ `ToolCall`+`ToolRet`, `grant` ≈
   `Consent`. tezgah's gate already reads a trace prefix for five rules
   (`unspent_grant`, loop, retry, sink, drift). The paper's contribution beyond
   that is monotonicity as an explicit design property, so a rule cannot be
   un-violated by later traffic.
2. **Cross-formalism agreement is the answer to a drift problem tezgah has by
   construction.** tezgah's gate exists twice - Python and the opencode
   JavaScript mirror - and is kept honest by a test
   (`tests/test_opencode_plugin.py`), i.e. by hand-written cases. C-Trace's
   method is to require two implementations to agree on *every* trace in a
   corpus, which is a stronger and automatable obligation than case-by-case
   pinning.
