---

Единый рабочий контракт для каждого используемого вами ИИ-ассистента по написанию кода — Claude Code,
opencode, Codex, Cursor и dsh от DeepSeek — внутри заданного набора
корневых каталогов репозиториев.

Если оставить их без присмотра, у каждого ассистента будут свои привычки: один отвечает на турецком, другой
на английском; один ищет всё через grep, другой делает запросы к графу кода; один говорит
«готово», не запустив ни одного теста. Tezgah устраняет эти расхождения. Откройте любой хост, и
вы получите тот же язык, ту же дисциплину и тот же стандарт доказательств.

Архитектура состоит из двух слоев. Правила существуют в единственном экземпляре в общем ядре; каждый хост получает
тонкий адаптер, который транслирует это ядро в понятный хосту формат.
Измените правило в одном месте, и все пять хостов увидят его — никакого пятикратного копирования
одного и того же текста.

<a id="what-it-enforces"></a>

## Что он контролирует

- **Отчеты на турецком языке с акцентом на результат.** Каждый ответ дается на турецком языке и начинается
  с результата или решения (BLUF), затем следуют пункты, отсортированные по степени влияния. Код, коммиты,
  документация и промпты субагентов остаются на английском; имена, команды CLI и строки
  ошибок никогда не переводятся.
- **Минимальный код (ponytail).** Самое «ленивое» изменение, которое действительно работает: YAGNI,
  затем переиспользование существующего хелпера, затем стандартная библиотека, затем нативная функция платформы,
  затем установленная зависимость, затем одна строка кода. Никаких незапрошенных абстракций.
  Валидация, обработка ошибок и безопасность никогда не упрощаются в ущерб качеству.
- **Поиск в первую очередь по графу кода.** Вопросы «где находится X», «кто вызывает Y», «что сломается, если
  изменится Z» направляются к графу `codebase-memory-mcp` (`search_graph`,
  `trace_path`, `search_code`), а не к grep. Использование grep остается уместным для точного поиска текста,
  конфигураций и файлов, не содержащих код.
- **Анализ приложений в первую очередь через accessibility.** Работающее веб- или мобильное приложение считывается
  через его дерево доступности (accessibility) / DOM / нативное дерево представлений, а не через скриншоты на каждом шаге.
  `analyze-app` охватывает браузер (Playwright MCP), iOS Simulator или эмулятор Android (Mobile MCP),
  а также опциональную веб-диагностику (Chrome DevTools MCP); скриншот — это явное,
  выполняемое по запросу действие для того, на что дерево не может дать ответ.
- **Внешнее второе мнение.** Перед принятием нетривиального или труднообратимого решения
  `~/.config/tezgah/bin/consult` параллельно опрашивает независимые модели через OpenRouter (или DeepSeek API
  с флагом `--provider deepseek`), и агент сообщает, в чем они
  сошлись или разошлись во мнениях.
- **Исследования через OpenResearch.** Когда маршрутизатор решает, что задача является исследовательской —
  обзор литературы, формирование и проверка гипотез, проведение экспериментов,
  создание исследовательского артефакта — он направляет работу через OpenResearch от alphaXiv (`orx`)
  и сначала загружает руководство `orx`, вместо того чтобы импровизировать с протоколом. Обычный
  поиск по коду остается на графе кода. Если `orx` отсутствует, маршрутизатор сообщает
  об этом и переключается на субагента хоста.
- **Честность при проверке.** Ничто не объявляется выполненным, протестированным или исправленным,
  пока не будет получен и просмотрен вывод. Упавший тест описывается как упавший с указанием
  точной ошибки, а о пропущенной проверке заявляется прямо.
- **Никакого упоминания ИИ, нигде.** Ничто из сохраненного или опубликованного — сообщения коммитов,
  слияний и тегов, тексты PR и issue, комментарии в коде, заголовки файлов, документация
  — не должно содержать упоминаний ассистента, модели, вендора или «ИИ». Использовать инструмент — нормально;
  подписывать свою работу его именем — нет.
- **Двухуровневая оркестрация.** Основной поток принимает решения и проверяет; дешевая
  модель (`~/.config/tezgah/bin/codegen`, OpenRouter по умолчанию или `--provider deepseek`) создает черновики
  ограниченных, хорошо специфицированных правок во временной директории. Ничто не попадает в репозиторий
  иначе как через маршрутизатор, а неудачный черновик автоматически возвращается
  к основной модели.
- **Субагенты для каждого репозитория.** При запуске сессии текущий репозиторий получает небольшой набор
  агентов с ограниченными возможностями (`tezgah-explorer`, `tezgah-reviewer`,
  `tezgah-researcher`, `tezgah-verifier`), а также `tezgah-orchestrator`, которые рендерятся
  в нативную среду каждого установленного хоста (Claude/Cursor `.claude/agents/`,
  opencode `.opencode/agents/` плюс инъекция конфигурации в реальном времени, Codex
  `.codex/agents/`) и игнорируются с помощью одного управляемого блока в `.gitignore`. В Claude
  список разрешенных агентов оркестратора `Agent(tezgah-*)` вступает в силу только тогда, когда он работает как
  основной поток (`claude --agent tezgah-orchestrator`); в качестве субагента этот список
  игнорируется. У dsh нет ролевой среды, поэтому его покрывает правило маршрутизатора из контракта.

<a id="supported-hosts"></a>

## Поддерживаемые хосты

| Хост | Способ интеграции | Строка статуса |
|---|---|---|
| **Claude Code** | локальный маркетплейс плагинов: хуки, команды, два агента только для чтения, стиль вывода | нативная `statusLine` |
| **opencode** | плагин + инструкции + MCP + сгенерированный маршрутизатор навыков (нативный список навыков запрещен), автоиндексация репозитория при первом сообщении | плагин TUI (нет командной statusLine) |
| **Codex** | `hooks.json` + навыки + MCP, включая шлюз `PreToolUse` | хук `systemMessage` (список элементов футера закрыт) |
| **Cursor** | `hooks.json` + навыки + MCP | `statusLine` в `cli-config.json` |
| **dsh** | мост хуков Claude Code + управляемый блок патчей (хуки, MCP, маршруты LLM, внешняя веб-строка статуса) | плагин Web UI: `tezgah-dsh-statusline` в заголовке сессии |

Шлюз Codex пропускает Bash, `exec_command`, `apply_patch`, Edit/Write, инструменты MCP,
и вызовы субагентов через ту же проверку, что и остальные хосты. В Claude запрет на
упоминание ИИ также обеспечивается механически: настройка `attribution`
очищается (`commit`, `pr`, `sessionUrl`), поэтому упоминания в коммитах и PR отключаются
на уровне источника.

### Строка статуса

Каждый хост отображает один и тот же однострочный чеклист из `tezgah-status`, поэтому они
не могут расходиться. Суть заключается в состоянии: отметка **зеленая**, когда правило активировано
и действует в текущей сессии, **желтая**, когда оно активировано, но работает по запросу (еще не использовалось),
и **красная**, когда оно отключено аварийным выключателем (kill switch). `idx` отдельно сообщает о готовности графа
(`✓` проиндексирован, `↻` устарел, `✗` не проиндексирован, `–` неприменимо), а
`plans N (M blk)` — об открытых планах. `tezgah-status --legend` выводит условные обозначения,
`--json` выдает те же сегменты для UI, а `--no-color` (или `NO_COLOR`)
принудительно включает обычный текст. Claude Code и Cursor раскрашивают нативную строку статуса;
TUI opencode раскрашивает собственный компонент и обновляется по шине событий хоста;
Web UI dsh раскрашивает компонент заголовка и обновляется только тогда, когда его вкладка
видима; Codex показывает обычную строку в `systemMessage`.

dsh запускает те же файлы хуков Claude через свой мост `dsh-hooks-claude-code`,
поэтому контракт запуска сессии, шлюз атрибуции и напоминание о первичном использовании grep
применяются и там. dsh предоставляет единственный инструмент `subagent`, поэтому запрет на использование
только grep для explorer неактивен — там просто нет субагента explorer, которому можно было бы отказать.
Песочница `workspace-write` в dsh по умолчанию ограничивает подпроцессы хуков рабочим пространством
и временной директорией платформы, поэтому tezgah записывает состояние своих хуков (отметки напоминаний, штамп индекса)
в доступный для записи резервный каталог там, вместо того чтобы падать из-за отказа в записи.
Воркер индексации графа не может записать кэш `codebase-memory-mcp` изнутри этой песочницы,
поэтому лаунчер `dsh` прогревает индекс в неограниченной оболочке пользователя перед загрузкой
dsh — новый репозиторий индексируется точно так же, как и на других хостах, с отметкой HEAD.
Сессия, запущенная без лаунчера, все равно получает четкий отчет о том, что
MCP-сервер вне песочницы обслуживает граф и нуждается в `index_repository` для репозитория,
который он не проиндексировал, вместо сырой ошибки `EPERM`. Управляемый
блок патчей также объявляет два OpenAI-совместимых маршрута LLM на адаптере pi-ai,
который монтирует базовая композиция: `openrouter` (`OPENROUTER_API_KEY`) и `deepseek`
(`DEEPSEEK_API_KEY`), которые можно выбрать наряду с нативным `deepseek-official`
по умолчанию. Ключи извлекаются из среды запуска или хранилища учетных данных платформы;
ни один из ключей не попадает в конфигурационный файл. tezgah-setup также помещает лаунчер `dsh`
в PATH (`~/.local/bin/dsh`), который находит установленный CLI в
`$DSH_HOME`, поэтому `dsh --profile web` работает из любой директории.

У dsh нет командной строки статуса, поэтому tezgah поставляет ее в виде плагина Web UI:
`tezgah-dsh-statusline`. Его хостовая часть отдает строку `tezgah-status` для
рабочего пространства сессии через аутентифицированный маршрут `/api/tezgah.status` (с
`?format=json` для цветного отображения); браузерная часть рендерит ее в заголовке сессии,
раскрашивая в зависимости от состояния с легендой по наведению/клику, и обновляется только пока
вкладка видима. `tezgah-setup`
привязывает плагин к веб-профилю и включает его с помощью управляемой строки в
`profiles/web/cordis.patch.yml` (только для web, так как хостовая часть внедряет
веб-сервис `connection`); профиль, который никогда не загружал `web`, пропускается
с подсказкой, чтобы избежать частичной записи. В режиме `headless` мост хуков внедряет
контракт SessionStart как собственный завершающий ход (его `agent/session-start`
вызывает `agent.inject()` отсоединенно, после того как одноразовая задача уже стала первым
сообщением), поэтому `dsh --profile headless "<task>"` тратит один дополнительный ход и,
для промпта с буквальным ответом, печатает реакцию модели на контракт, а не ответ
на задачу; интерактивные веб-сессии при этом не затрагиваются.

`bin/tezgah-setup --install` также запускает `orx install-skills` для Claude,
Codex, opencode и Cursor, когда `orx` находится в PATH, чтобы у правила исследования было
руководство для загрузки. Файлы-прослойки (shims) принадлежат orx, поэтому tezgah только запускает этот установщик
и никогда не включает их в список для удаления. У dsh нет обвязки orx; правило исследования
там откатывается к `orx skill` в оболочке.

Плагин Claude также поставляет двух агентов только для чтения. `agents/tezgah-explorer.md`
выполняет поиск по коду с помощью графа и возвращает доказательства в формате `file:line`;
`agents/tezgah-reviewer.md` превращает diff в набор затронутых элементов с помощью
`detect_changes`, а затем ищет реальные дефекты. У обоих отключены инструменты записи и
выполнения команд; их вывод носит рекомендательный характер.

### Анализ приложений

`analyze-app` управляет запущенным приложением через его дерево доступности (accessibility tree).
Цикл по умолчанию: открыть, прочитать дерево, выполнить действие, пронаблюдать за консолью/сетью/логами,
и перечитать дерево — скриншот является явным действием для того, на что дерево не может
дать ответ (canvas, игра, анимация, визуальная регрессия на уровне пикселей). Этот навык представляет собой
единый путь для всех хостов; серверы под ним — это одна общая спецификация в
`hooks/tezgah_apps.py`:

| Сервер | Цель | Способ интеграции |
|---|---|---|
| `playwright` (`@playwright/mcp`) | веб-страницы, инструменты `browser_*` | opencode, Codex, Cursor, Claude (плагин `.mcp.json`) |
| `mobile-mcp` (`@mobilenext/mobile-mcp`) | iOS Simulator / эмулятор Android, инструменты `mobile_*` | то же самое |
| `chrome-devtools` (опционально, `--devtools`) | трассировки веб-производительности, глубокий анализ сети, консоль с source-map | то же самое |

Браузер по умолчанию запускается в **изолированном** профиле, поэтому запуск никогда не затрагивает
ваше реальное состояние Chrome; анализ флоу с авторизацией — это намеренное подключение
(`--cdp-endpoint` или расширение Playwright), а не действие по умолчанию. Скриншоты,
трассировки и дампы дерева сохраняются в `~/.cache/tezgah/apps` (переопределяется через
`TEZGAH_ARTIFACTS`), и агент получает обратно путь, а не байты изображения напрямую.
Серверы запускаются через `npx`, поэтому им нужен node, но не требуется собственная установка;
`tezgah-setup --install --devtools` добавляет опциональный сервер веб-диагностики.
dsh подключает те же два сервера через свой мост `dsh-mcp-client`
(`serverName` / `command` / `args` / `env`, подтверждено опубликованной
схемой конфигурации), а Claude получает их из `.mcp.json` плагина
(`claude plugin details tezgah` показывает 2 MCP-сервера, и оба подключаются).
`mobile-mcp` — это часть, требующая больше усилий: macOS может запросить разрешения на Универсальный доступ (Accessibility) /
Запись экрана (Screen-Recording), а дерево представлений может отваливаться под нагрузкой, поэтому навык
повторяет попытку получения дерева перед тем, как откатиться к скриншоту.

CI выполняет детерминированное рукопожатие (handshake) для обоих серверов (без браузера, без устройства):
`TEZGAH_E2E_STRICT=1 python3 tests/e2e_analyze_wiring.py`. Два опциональных локальных
smoke-теста идут дальше: `TEZGAH_E2E_APPS=1 python3 tests/e2e_analyze_web.py` запускает
Playwright MCP, выполняет навигацию и читает снимок без скриншота;
`TEZGAH_E2E_APPS=1 python3 tests/e2e_analyze_mobile.py` запускает Mobile MCP, проверяет
инструменты дерева представлений и выводит список устройств. Они печатают `SKIP: ...`, когда node,
сборка браузера или устройство отсутствует.

<a id="install"></a>

## Установка

Требуется Python 3.8+. node + npm необходимы для хоста dsh и, вместе с `pnpm`,
для его веб-строки статуса. Опциональные интеграции деградируют изящно:
`codebase-memory-mcp` в PATH обеспечивает работу графа; ключ модели обеспечивает работу `consult`
и `codegen` — OpenRouter по умолчанию (`OPENROUTER_API_KEY` или
`~/.config/openrouter/key`), либо DeepSeek API с флагом `--provider deepseek`
(`DEEPSEEK_API_KEY` или `~/.config/deepseek/key`); а `orx` от OpenResearch в
PATH дает правилу исследования инструмент для управления. Если ключ выбранного провайдера
отсутствует, tezgah сообщает об этом, а не делает вид, что все работает.

Склонируйте репозиторий, затем активируйте каждый обнаруженный хост за один проход:

```bash
git clone https://github.com/r1z4x/tezgah.git ~/Projects/tezgah
cd ~/Projects/tezgah
bin/tezgah-setup --install
```

`--install` также устанавливает недостающие опциональные инструменты, запуская собственный установщик
каждого вендора **по сети**: `orx`
(`openresearch.sh/install.sh`), `cursor-agent` (`cursor.com/install`), `dsh`
(его домашний профиль через `npx`) и `pnpm`, когда он нужен dsh (через `npm`) —
включая `curl ... | sh`. Ни для одного из них не требуется sudo; процесс выполнения записывается в
`~/.config/tezgah/install.log`. Предварительный просмотр доступен с `--dry-run`, пропуск — с
`--no-deps` (полезно в CI), а установка только инструментов — с `--deps`. Инструменты
попадают в `~/.local/bin` или `~/.cargo/bin`, поэтому может потребоваться перезапуск оболочки,
чтобы они появились в PATH; собственные проверки tezgah в любом случае ищут в этих директориях,
поэтому неинтерактивная оболочка все равно сообщает об их наличии.

Если предыдущая установка уже присутствует, сначала импортируйте ее — она будет перемещена,
а не удалена:

```bash
bin/tezgah-setup --adopt
```

Claude Code устанавливается через собственный канал плагинов:

```bash
claude plugin marketplace add ~/Projects/tezgah
claude plugin install tezgah@rizacan-local
```

При необходимости явно ограничьте установку:

```bash
bin/tezgah-setup --install --hosts claude,codex,opencode,cursor,dsh
bin/tezgah-setup --roots ~/work:~/oss --install
```

<a id="day-to-day"></a>

## Повседневное использование

Ничего запускать не нужно: правила загружаются при старте хоста. Стоит знать несколько команд:

| Команда | Назначение |
|---|---|
| `bin/tezgah-setup` | Отчет о том, что активировано, для каждого хоста |
| `bin/tezgah-status [PATH]` | Показать, активны ли правила в этом репозитории |
| `bin/tezgah-setup --status [PATH]` | Вывести чеклист активированных/используемых правил |
| `bin/tezgah-setup --deps [--dry-run]` | Установить недостающие опциональные инструменты (orx, cursor-agent, dsh) |
| `bin/tezgah-doctor [--clean] [--prune-sessions DAYS]` | Отчет об использовании диска платформой; `--clean` удаляет старые логи индексов и выполняет vacuum БД opencode; `--prune-sessions` удаляет неактивные сессии (единственное действие, которое реально уменьшает размер БД) |
| `/plan-add` | Превратить часть работы в отслеживаемый план |
| `/plan-status` | Свести открытые планы и выбрать следующий |
| `/plan-sync` | Закрыть завершенные планы |
| `bin/tezgah-setup --version` | Вывести версию плагина |
| `bin/tezgah-setup --uninstall` | Удалить только символические ссылки tezgah, записи хуков хоста и управляемый блок dsh |

<a id="configuration"></a>

## Конфигурация

Tezgah активируется только в настроенных корневых каталогах; везде в других местах он бездействует.

- Корневой каталог по умолчанию: `~/Projects`.
- `~/.config/tezgah/config.json`: `{"roots": ["~/Projects", "~/work"]}`.
- `TEZGAH_ROOTS` (список, разделенный разделителем путей) переопределяет файл для разовых запусков и CI.

Аварийные выключатели (kill switches) находятся в `~/.config/tezgah/`. Каждый из них удаляет свое правило из
текста, внедряемого в сессию, поэтому правило действительно перестает работать:

| Выключатель | Что отключает |
|---|---|
| `exec-mode.off` | отчеты на турецком языке с акцентом на результат |
| `ponytail-auto.off` | правило минимального кода |
| `spec-off` | правило «спецификация перед разработкой» |
| `consult-off` | правило внешнего второго мнения |
| `research-off` | маршрутизацию исследовательских задач в OpenResearch |
| `orchestrate-off` | делегирование субагентам (добавляет строку о запрете делегирования) |
| `reminder-off` | текст напоминания на каждом ходу |
| `pretooluse-off` | сам шлюз PreToolUse (атрибуция, explorer, напоминание о grep) |

Для каждого репозитория файлы `.no-ponytail`, `.no-cbm` и `.no-lessons` отключают правило минимального кода,
правило графа кода (и его автоиндексацию) и реестр уроков соответственно.

Когда пользователь указывает на ошибку, агент добавляет однострочный урок в файл репозитория
`.tezgah/lessons.md`; самые последние строки внедряются при запуске сессии, чтобы
та же ошибка не могла незаметно повториться.

<a id="cost"></a>

## Затраты

Измерено на этой машине (macOS, Python 3.10), а не оценено приблизительно:

- **Контекст.** При запуске сессии внедряется ~4,8 КБ (~1,2 тыс. токенов) текста контракта.
  В Codex напоминание размером 480 байт добавляется на каждом ходу; у Claude и других хостов
  нет хука на каждый ход, поэтому их затраты на ход равны нулю. Полный навык `tezgah-contract`
  (~19,9 тыс. символов) оплачивается только тогда, когда задача его загружает. В opencode
  контракт поставляется как файл инструкций размером ~5,5 КБ. В противном случае opencode
  внедрял бы ~53 КБ текста с названиями/описаниями/расположением навыков в системный промпт
  каждой сессии; tezgah запрещает этот список (`permission.skill = deny`) и поставляет
  сгенерированный маршрутизатор навыков размером ~16 КБ вместо этого, поэтому навык находится
  путем чтения его пути `SKILL.md` из маршрутизатора.
- **Задержка.** Хуки — это отдельные процессы Python, поэтому доминирует запуск интерпретатора
  (~19 мс). Поверх этого запуск сессии добавляет ~25 мс, вызов инструмента через шлюз
  (Bash/Grep/Task) добавляет ~9 мс, а сегмент Stop в Codex добавляет ~15 мс на каждый ход.
- **Диск.** Установка занимает ~58 мс, и каждый файл, который перезаписывает tezgah, сохраняется
  один раз как `<file>.tezgah-bak`.

Окупаемость проявляется в вопросах о вызывающем коде. В одном реальном репозитории стандартный `grep`
проигнорировал нужную папку и ничего не нашел; с отключенным игнорированием это заняло
3,95 с и все равно смешало определения с местами вызовов. Граф кода ответил на
тот же вопрос за 16 мс, перечислив только 8 истинных мест вызовов.

opencode также настроен на гигиену контекста в длинных сессиях: `tezgah-setup --install`
устанавливает `compaction.prune`, чтобы старые результаты работы инструментов удалялись из промпта,
а не отправлялись заново на каждом шаге, а список `watcher.ignore` не пускает наблюдатель за файлами
в `.git`, `node_modules` и директории сборки. Оба параметра объединяются — явное значение пользователя
имеет приоритет. Это важно, потому что opencode выполняет автосжатие только вблизи предела
контекста модели (для модели на 1 млн токенов — около 980 тыс.), поэтому без очистки рабочий набор
разрастается до сотен тысяч токенов. `bin/tezgah-doctor` сообщает об итоговом занимаемом месте
на диске; `--prune-sessions DAYS` удаляет неактивные сессии через CLI opencode,
что является единственным действием, которое реально уменьшает базу данных — один только
VACUUM не может этого сделать, так как все его страницы активны.

<a id="development"></a>

## Разработка

```bash
python3 -m unittest discover -s tests -v   # stdlib test suite
pip install -r requirements-dev.txt        # pinned ruff, the only dev dep
ruff check .                               # lint (config in pyproject.toml)
```

CI запускается как на Python 3.10, так и на 3.12. Чтобы обновить установленную копию Claude из этого чекаута,
используйте `bin/tezgah-setup --sync` и проверьте манифест с помощью
`claude plugin validate .claude-plugin/plugin.json`. При повышении версии обновляйте
`.claude-plugin/plugin.json` и `.claude-plugin/marketplace.json`
вместе — они должны совпадать.

`codebase-memory-mcp` устанавливается пользователем. Хуки и файлы Orca не являются
частью этого проекта и остаются нетронутыми. Claude получает постоянно включенное ядро
из хука SessionStart; `output-styles/tezgah.md` является дубликатом для сборок,
которые загружают стили вывода плагинов, поэтому хук является авторитетным путем.

<a id="contributing"></a>

## Участие в разработке

Небольшие, узконаправленные изменения принять проще всего. Правило должно находиться в
общем ядре (`hooks/`), если только оно не является специфичным для конкретного хоста; отличия хостов
должны находиться в их адаптерах в `hosts/<name>/`. Делайте diff настолько коротким,
насколько это возможно при сохранении корректности — собственное правило минимального кода проекта
применяется и к самому проекту.

Перед открытием pull request запустите те же три проверки, которые выполняет CI:

```bash
python3 -m compileall -q hooks hosts bin statusline.py   # byte-compile every script
python3 -m unittest discover -s tests                     # stdlib test suite
ruff check .                                              # lint; config in pyproject.toml
```

`ruff` устанавливается из `requirements-dev.txt` (`pip install -r requirements-dev.txt`),
что является единственной зависимостью для разработки.

<a id="security"></a>

## Безопасность

Сообщайте об уязвимостях приватно через рекомендации по безопасности GitHub
(вкладка **Security** → **Report a vulnerability**), а не через публичные issue.

tezgah запускает хуки оболочки, записывает конфигурацию хоста и внедряет текст в каждую
сессию, поэтому все, что заставляет хук выполнять контролируемый злоумышленником код, допускает утечку
ключа в конфигурационный файл, расширяет песочницу или позволяет содержимому репозитория повысить
свои привилегии до текста инструкций, входит в область видимости. Укажите хост, версию tezgah
(`bin/tezgah-setup --version`) и минимальный пример для воспроизведения.
