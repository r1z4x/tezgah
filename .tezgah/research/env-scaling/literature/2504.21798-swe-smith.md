arXiv: https://arxiv.org/abs/2504.21798 — John Yang, Kilian Lieret, Carlos E. Jimenez, Alexander
Wettig, Kabir Khandpur, Yanzhe Zhang, Binyuan Hui, Ofir Press, Ludwig Schmidt, Diyi Yang — 2025-04-30,
cs.SE / cs.AI / cs.CL. Report read in full; the arXiv abstract was fetched as the second record;
code and assets at https://github.com/SWE-bench/SWE-smith and https://swesmith.com.

## What it is
The environment-*generation* pipeline that anchors the SWE half of this literature: given any
Python codebase, SWE-smith first builds one execution environment for the whole repository (a
single Docker image, one per repository) and then synthesizes hundreds to thousands of task
instances inside it by breaking existing passing tests. Five bug-injection strategies are
measured by yield: LM Modify, LM Rewrite, Procedural Modification (AST edits), Combine Bugs,
and PR Mirror (an LM is prompted to "undo" a merged pull request in the current tree).

Numbers, the authors' own:
- "50,137 task instances" across "128 real-world Python GitHub repositories", described as "an
  order of magnitude larger" than prior work.
- Storage: "SWE-smith's 128 Docker images require a total of 295 GBs, a fraction of the
  estimated 50-150 TBs that would be needed to store 50,000 instances using SWE-bench's
  instance-specific Docker approach".
- "The entire data collection process for SWE-smith cost approximately $1360".
- Yields: Combine Bugs 96.9% at effectively zero cost; LM Modify 56.0% at 0.38¢ per candidate;
  Procedural Modification 40.2% at effectively zero cost; LM Rewrite 35.0% at 3.93¢; PR Mirror
  33.8% at 5.53¢.
- The trained model: "SWE-agent-LM-32B, achieving 40.2% Pass@1 resolve rate on the SWE-bench
  Verified benchmark, state of the art among open source models" (abstract).

## Why it is in this line
It is one of the three generation pipelines the question names, and the one that made the
environment the unit of scale rather than the instance: one environment per repository, many
tasks per environment. That inversion - and its storage and dollar figures - is the concrete
shape of "environment scaling" in 2025, and the baseline EnvHarness later beats by 2.46 points
on SWE-bench Verified with 5.11 fewer steps. Its own contribution is a *corpus*, though: it
generates no policy-side loop, which is why it addresses the environment axis and not the
training axis.
